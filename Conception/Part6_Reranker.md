## 리랭커

- Reranker는 현대적으로 두 단계 검색 시스탬(Two-Stage Retrieval System)에서 사용되는 핵심 컴퍼넌트
- 대규모 데이터셋에서 효율적이고 정확한 검색을 수행하기 위해 설계, 주로 첫 단계인 Retriever가 찾아낸 문서들의 순위를 재 조정하는 역할을 함

    1. Query -> embding 유사도 검사진행
    2. VectorDB // Query 문서화
    3. 유사도를 통한 scoring(Retriver)
    4. Reranker를 진행
    5. 다시 검사를 시작함
    6. 순위 재조정
    7. 보다 정확한 답을 얻을 수 있다.

## 개요
- Reranker은 검색에서 2번째 단계에서 진행에서 작도하며, 초기 검색 결과의 정확도를 향상시키기 위한것을 목표로 함
- Retriever가 대규모 문서 집합에서 관련성 있는 후보 문서들을 빠르게 추출한 후, Reranker는 이 후보 문서들을 좀더 정교화 해서 최종적인 순위를 결정

- 즉, 단순 유사도만을 사용하면 정확도가 낮다는 말?
    - 애초에 Retrieve를 사용허지 않아도되는거아닌가?
- 리트리버 방식
    - 질문 -> vector 변환 [0.1,0.2]
    - 문서 1, 문서2, 문서3 -> 개별적으로 변환해서 저장
    - 개별적으로 모두 인코딩 한 다음에 질문과 문서들의 유사도를 비교
- 리랭커
    - 질문과 문서를 동시에 인코딩을 한 다음 원하는 답을 얻어낸다.
    - 즉, 쿼리와 각 후보 문서들을 쌍으로 결합하여 처리한다.
    - Cross ecoding 방식은 정확하지만, 계산 비용이 높다
    - 계산하는 시간과 토큰이 굉장히 많이든다.

- 리트리버로 후보군을 만들어 낸다.
- Reranker기반으로 유사도계산을 통해 정답을 준다
